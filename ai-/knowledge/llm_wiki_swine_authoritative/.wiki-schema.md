# Wiki Schema

## Domain

- Species/domain: swine disease, swine drug, production medicine, evaluation, and golden dataset governance.
- Language: Chinese primary content with stable ASCII IDs.

## Mandatory Governance Contract

All maintenance operations must comply with:

- `WIKI_UPDATE_MANDATORY_SHORT_CARD.md`
- `WIKI_UPDATE_SCENARIO_SHORT_CARD.md`
- `WIKI_MAINTENANCE_GUIDE.md`
- `WIKI_DATA_SOURCE_CRUD_GOVERNANCE.md`

This applies to source intake, web-derived information, local Markdown/PDF/Word/Excel extraction, fact changes, runtime page edits, evidence expansion migration, rule card changes, export/index/graph rebuilds, and gold dataset or pilot dataset generation.

All modifying update commands should run through `tools/run_guarded_wiki_update.py`, which runs governance preflight before the update and full validation after the update.

If an operation changes, overwrites, downgrades, archives, excludes, migrates, or deletes old data, the change record must explain the factual reason: rule update, obsolete source version, source conflict, extraction error, encoding damage, duplicate data, page-size compaction, or task-gate change. No source or fact should be silently overwritten or deleted.

## Source Contract

Source pages must include:

- `source_id`
- `source_path` or `external_url`
- `source_type`
- `authority_level`
- `source_status`
- `supports`
- `does_not_support`

`evidence_status` may remain as a legacy audit field during migration, but it must not be the primary usability gate.

## Usability Contract

Facts and runtime pages should be judged by:

- `source_status`: `source_anchored`, `source_missing`, `source_conflicted`, `source_damaged`, `source_level_mismatch`
- `fact_validity`: `valid`, `conflicted`, `out_of_scope`, `encoding_damaged`, `obsolete_or_superseded`, `insufficient_anchor`
- `authority_level`: `A0`, `A1`, `A2`, `SRC`, `RC`, `RULE`
- `risk_class`: `normal_clinical`, `diagnostic`, `drug_boundary`, `high_regulatory`, `withdrawal_mrl_residue`, `food_safety`, `public_health`
- `task_use_status`: `train_ready`, `eval_ready`, `generation_ready_limited`, `retrieval_only`, `blocked`

A fact can be used when the source is clear, the data is valid, and the source authority level matches the requested task. Legacy `HUMAN_REVIEWED` and `NEEDS_REVIEW` values are migration signals, not direct allow/block decisions.

## Gold Dataset Contract

Runtime manifest records that can feed dataset production must include:

- `task_use_status`
- `gold_dataset_role`
- `allowed_question_types`
- `blocked_question_types`

`train_ready` records may enter SFT only when answers preserve source/fact/rule provenance. `eval_ready` records may enter evaluation and trap construction. `generation_ready_limited` records may produce bounded candidates but not unrestricted high-risk conclusions. `retrieval_only` records are for alias, recall, and routing. `blocked` records do not enter generation or evaluation.

Drug records must also be represented in `exports/drug_gold_role_index.csv` as one of:

- `boundary_only`
- `negative_trap`
- `exclude_from_positive_generation`
- `positive_label_candidate`

Drug positive generation is allowed only when A0 or label-level equivalent evidence supports the requested claim. SRC/A1/A2 clinical or textbook evidence may support retrieval, boundaries, and negative traps, but it must not become standalone dose, course, withdrawal, MRL, residue, saleability, or food-safety output.

## Runtime Boundary

Default production and evaluation retrieval must use `exports/runtime_core_manifest.json` as the allowlist and `exports/runtime_exclude_patterns.json` as the denylist. Raw files, issue notes, graph exports, sessions, large treatment matrices, and construction artifacts are not default runtime context.
