# Wiki Schema

## Core Layers

- `raw/`: immutable originals.
- `wiki/sources/`: source summaries and standards anchors.
- `wiki/diseases/`, `wiki/syndromes/`, `wiki/drugs/`, `wiki/rules/`: object-level compiled knowledge pages.
- `wiki/topics/`: task-oriented entry pages that route readers across diseases, drugs, rules, and sources.
- `exports/`: compact indexes and facts for tooling.

## Maintenance Rules

- Do not duplicate a source into multiple page types when one source page is enough.
- Standards are a subtype of source, not a separate summary layer.
- Prefer updating existing disease, drug, topic, and source pages over creating near-duplicate pages.
- Keep topic pages workflow-oriented and synthetic; keep source pages evidentiary.
- Preserve links back to raw originals for every authoritative claim.
- Every exported fact must include `evidence_status`: `EXTRACTED`, `INFERRED`, `HUMAN_REVIEWED`, or `NEEDS_REVIEW`.
- Use `NEEDS_REVIEW` for drug labels, withdrawal periods, or disease guidance that lacks a direct authoritative source page.
- Regulatory claims must resolve to an A0/A1 source before they can be used in golden dataset answers.

## Query Workflow

- Read `index.md` first, then start from the task page in `wiki/topics/` that matches the question.
- Use disease/drug/rule pages for compiled conclusions and source pages for final provenance checks.
- Save high-value synthesis back into the smallest existing workflow page that can carry it instead of creating shallow duplicates.

## Lint Workflow

- Run `python scripts/lint_chicken_wiki.py` after rebuilding or manually editing the wiki.
- Treat broken internal links, missing source pages, missing evidence status, and mojibake markers as blocking issues.
- Treat coverage gaps and `NEEDS_REVIEW` facts as dataset-readiness warnings unless the target split is explicitly a review/refusal split.
