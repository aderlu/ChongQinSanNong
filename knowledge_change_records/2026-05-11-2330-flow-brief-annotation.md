# 总体调用链职责标注补充记录

## 1. 修改概述

本次对精简汇报文档的“总体调用链”部分做了职责标注，让每个脚本名字后面都直接带上作用说明。

修改文件：

- `ai-/knowledge/llm_wiki_swine_authoritative/WIKI_GUARDED_UPDATE_FLOW_BRIEF_CN.md`

## 2. 修改前存在的问题

原来的总体调用链虽然已经列出所有脚本，但只是按顺序展示，读者需要自己理解每个脚本的作用。对于快速汇报来说，这不够直观。

## 3. 本次新增内容

在调用链每个节点后补充了职责说明，包括：

- CRUD 决策文件的作用。
- `run_guarded_wiki_update.py` 的固定入口职责。
- `audit_governance_compliance.py` 的治理合规检查职责。
- `audit_crud_decision.py` 的 CRUD 门禁职责。
- `args.command` 的实际写入职责。
- `run_swine_wiki_maintenance_checks.py` 的总验收职责。
- 各子验收脚本的具体职责。
- 运行结果 JSON 和历史日志的用途。

## 4. 修改后解决的问题

现在看到调用链就能直接知道：

- 哪个脚本是入口。
- 哪个脚本负责门禁。
- 哪个脚本负责落库。
- 哪个脚本负责验收。
- 哪个脚本负责证据输出。

## 5. 预计效果

这会让汇报材料更适合快速讲解，不需要再额外解释每个脚本的功能。

## 6. 编码保护措施

本次仅修改精简文档中的调用链文字说明，没有改动代码逻辑，风险较低。
