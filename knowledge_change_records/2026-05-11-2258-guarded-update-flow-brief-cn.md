# 受控更新程序调用流程精简中文说明新增记录

## 1. 修改概述

本次新增一份精简中文汇报文档，用于清晰说明 LLM Wiki 受控更新程序的完整调用流程、执行流程、环节衔接和失败中断点。

新增文件：

- `ai-/knowledge/llm_wiki_swine_authoritative/WIKI_GUARDED_UPDATE_FLOW_BRIEF_CN.md`

## 2. 修改前存在的问题

此前中文说明文档内容较完整，但篇幅较长，不适合作为简洁汇报材料。尤其在需要快速说明“程序如何调用、每一步如何连接下一步、失败在哪里停止”时，长文档不够直观。

## 3. 本次新增内容

新增精简文档保留以下核心内容：

- 总体调用链。
- CRUD 决策文件如何进入门禁检查。
- `run_guarded_wiki_update.py` 如何解析 `args.command`。
- `PREFLIGHT` 如何调用治理检查和 CRUD 检查。
- 门禁通过后如何调用具体更新命令。
- 更新成功后如何通过 `POSTCHECK` 调用总验收脚本。
- 总验收脚本如何通过 `CHECKS` 调用各验收子流程。
- 验收结果如何通过 `write_report(payload)` 写入 JSON 和 JSONL。
- 运行证据如何进入 `knowledge_change_records` 工作留痕。
- 每个环节的失败中断点。

## 4. 修改后解决的问题

修改后，可以用较短篇幅说明完整执行链路：

1. 先有 CRUD 决策。
2. 固定入口启动。
3. 更新前门禁检查。
4. 门禁通过后执行更新命令。
5. 更新成功后执行完整验收。
6. 写入机器证据。
7. 形成工作留痕。

该文档更适合用于会议汇报、流程说明和快速审计解释。

## 5. 预计效果

精简文档可以帮助汇报对象快速理解：

- 哪个脚本调用哪个脚本。
- 哪个结果传给下一步。
- 哪个环节负责真正写数据。
- 哪个环节负责更新后验收。
- 哪些文件证明流程执行过。

## 6. 编码保护措施

本次采用新增 UTF-8 Markdown 文件方式，没有覆盖原有长版中文文档，降低乱码风险。
